# 独立性能测量

从 v0.2.1 起，验收命令支持 `-isolate`（分进程模式）。公共库接口和第 2 版协议保持兼容。

## 运行

在仓库根目录执行：

```sh
go run ./cmd/check -isolate -rooms 8 -clients 16 -duration 10m -resume-every 30s -report reports/local/isolated.json
```

每房间 16 个客户端、16 个道具。父进程通过标准输入输出协调两个子进程：服务器负责房间和传输；负载进程负责全部参考客户端、续接和弱网代理。两者使用真实加密网络连接，证书私钥仅保存在服务器内存；续接凭证不进入控制消息和报告。

省略 `-isolate`（分进程模式）时沿用同进程验收。默认报告路径改为 `reports/local/soak.json`，避免覆盖历史报告。可用 `-cpuprofile`（处理器采样文件）记录性能采样：同进程模式记录整个验收进程，分进程模式只记录服务器子进程。

```sh
go run ./cmd/check -isolate -duration 20s -clients 16 -resume-every 3s -rtt 150ms -jitter 30ms -loss 0.05 -duplicate 0.02 -reorder 0.02 -report reports/local/weak-150ms.json
```

参数及概率范围与同进程模式相同。三档弱网使用往返延迟 0、150、300 毫秒；零往返延迟档仍叠加指定的抖动和丢包。

## 统计口径

| 报告字段 | 含义 |
|---|---|
| `Mode`（运行模式） | `in-process`（同进程）或 `isolated`（分进程） |
| `ServerProcess`（服务器进程） | 服务器进程编号、开始时间、最终状态采样时间、资源序列及汇总 |
| `LoadProcess`（负载进程） | 客户端及启用的弱网代理，字段与服务器进程相同 |
| 顶层处理器秒数、分配总量、资源采样 | 分进程模式为两个业务子进程合计，不包含协调父进程 |
| 单核／全机处理器百分比 | 处理器时间除以测量时长；全机口径再除以逻辑处理器数量 |
| 顶层测量时长 | 两个业务子进程实际测量时长的较大值；合计速率使用这个分母 |
| 房间耗时、连接数、保留会话、队列与发送字节 | 来自服务器房间；带宽速率使用服务器测量时长 |
| `AllocatedBytes`（累计分配字节） | 测量窗口内的分配量，区别于回收后的在用堆内存 |

所有连接建立完成后，父进程下发共同开始时点；报告保留两个进程各自的实际开始时间。每三十秒同时请求资源采样，分别主动垃圾回收后读取堆大小。服务器房间仍在推进，采样、控制消息和可选性能采样的成本包含在对应进程数据内。

长测分别检查两个进程：至少十分钟、有效采样覆盖第六十秒及结束时点，末次堆大小不得超过第六十秒基线加 25% 加 4 MiB（兆二进制字节），后台任务数不得超过基线加每房间 16 个。总检查结果要求两者都通过。短测的 `MemoryChecked`（已执行长期检查）和 `MemoryBounded`（增长受限）均为假，不代表内存失败。

## 一致性与退出

负载结束时先等待已进入的移动提交和续接操作完成，再恢复正常网络、停止移动并持续发送零输入。从这个恢复边界起等待一秒，然后让两个进程采集各房间权威状态和客户端预测。比较实体编号、代数、归属、动态标记、状态字节及本地预测；不要求不同采样瞬间的服务器帧号和零输入确认编号完全一致。

资源回收采样安排在最终状态采集之后，避免垃圾回收人为延长收敛等待。报告记录两个进程的实际状态采集时刻；这是“一秒等待后的观测”，不是连续观测得到的最早收敛时间。

子进程异常退出、控制通信失败、取消或超时会使验收失败。父进程关闭输入管道请求退出，三秒内未退出则终止该子进程，并等待系统回收。测试报告写出失败原因，程序返回非零退出码。强制终止整个进程树、机器断电不属于正常清理保证。

## 证据边界

分进程能分清服务器和负载程序成本，但仍共享同一台机器和回环网络。它不证明公网时延、跨机器吞吐或生产容量。带宽只统计服务器下行应用负载，不包含传输头、加密、确认、重传及上行。单步第 99 百分位低于十毫秒不等于每一步均低于十毫秒。

当前与历史数据见[验收报告索引](../reports/README.md)。v0.2.0 的同进程资源值不能直接与本版服务器独立值相减来宣称性能提升。

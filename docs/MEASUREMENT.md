# 独立性能测量

从 v0.2.1 起，验收命令支持 `-isolate`（分进程模式）。v0.3.0 升级为第 3 版协议，保留连接、游戏及续接方法语义，并扩展同协议完整／差量对照和逐实体显示时效测量。

## 运行

在仓库根目录执行：

```sh
go run ./cmd/check -isolate -rooms 8 -clients 16 -duration 10m -resume-every 30s -report reports/local/isolated.json
```

每房间 16 个客户端、16 个道具。父进程通过标准输入输出协调两个子进程：服务器负责房间和传输；负载进程负责全部参考客户端、续接和弱网代理。两者使用真实加密网络连接，证书私钥仅保存在服务器内存；续接凭证不进入控制消息和报告。

省略 `-isolate`（分进程模式）时沿用同进程验收。默认报告路径改为 `reports/local/soak.json`，避免覆盖历史报告。可用 `-cpuprofile`（处理器采样文件）记录性能采样：同进程模式记录整个验收进程，分进程模式只记录服务器子进程。

```sh
go run ./cmd/check -isolate -duration 20s -clients 16 -resume-every 3s -rtt 150ms -jitter 30ms -loss 0.05 -duplicate 0.02 -reorder 0.02 -report reports/local/weak-150ms.json
```

参数及概率范围与同进程模式相同。三档弱网使用往返延迟 0、150、300 毫秒；零往返延迟档仍叠加指定的抖动和丢包。

## 统计口径

| 报告字段 | 含义 |
|---|---|
| `Mode`（运行模式） | `in-process`（同进程）或 `isolated`（分进程） |
| `ServerProcess`（服务器进程） | 服务器进程编号、开始时间、最终状态采样时间、资源序列及汇总 |
| `LoadProcess`（负载进程） | 客户端及启用的弱网代理，字段与服务器进程相同 |
| 顶层处理器秒数、分配总量、资源采样 | 分进程模式为两个业务子进程合计，不包含协调父进程 |
| 单核／全机处理器百分比 | 处理器时间除以测量时长；全机口径再除以逻辑处理器数量 |
| 顶层测量时长 | 两个业务子进程实际测量时长的较大值；合计速率使用这个分母 |
| 房间耗时、连接数、保留会话、队列与发送字节 | 来自服务器房间；带宽速率使用服务器测量时长 |
| `AllocatedBytes`（累计分配字节） | 测量窗口内的分配量，区别于回收后的在用堆内存 |

所有连接建立完成后，父进程下发共同开始时点；报告保留两个进程各自的实际开始时间。每三十秒同时请求资源采样，分别主动垃圾回收后读取堆大小。服务器房间仍在推进，采样、控制消息和可选性能采样的成本包含在对应进程数据内。

长测分别检查两个进程：至少十分钟、有效采样覆盖第六十秒及结束时点，末次堆大小不得超过第六十秒基线加 25% 加 4 MiB（兆二进制字节），后台任务数不得超过基线加每房间 16 个。总检查结果要求两者都通过。短测的 `MemoryChecked`（已执行长期检查）和 `MemoryBounded`（增长受限）均为假，不代表内存失败。

## 一致性与退出

演示负载结束时先等待已进入的移动提交和续接操作完成，再恢复正常网络、停止移动并持续发送零输入；一秒后采集各房间权威状态和客户端预测。比较实体编号、代数、归属、动态标记、状态字节及本地预测；不要求不同采样瞬间的服务器帧号和零输入确认编号完全一致。标准负载额外持续观察远端显示，并禁止恢复期间可靠状态纠正，见下文。

资源回收采样安排在最终状态采集之后，避免垃圾回收人为延长收敛等待。报告记录两个进程开始处理终点采集的时刻；各进程再逐房间或客户端读取状态和计数，不能将此时间理解为全部字段的共同截止时刻。演示负载的终点是一秒等待后的观测，标准负载另有下述连续恢复观察。

子进程异常退出、控制通信失败、取消或超时会使验收失败。父进程关闭输入管道请求退出，三秒内未退出则终止该子进程，并等待系统回收。测试报告写出失败原因，程序返回非零退出码。强制终止整个进程树、机器断电不属于正常清理保证。

## 证据边界

分进程能分清服务器和负载程序成本，但仍共享同一台机器和回环网络。它不证明公网时延、跨机器吞吐或生产容量。旧下行速率字段保留原口径，新总应用字节包含双向应用发送；传输头、加密、传输确认和重传均不计入。单步第 99 百分位低于十毫秒不等于每一步均低于十毫秒。

当前与历史数据见[验收报告索引](../reports/README.md)。v0.2.0 的同进程资源值不能直接与本版服务器独立值相减来宣称性能提升。

## 第 3 版对照与显示时效

-workload（负载选择）默认 arena（二维演示），motion（稀疏运动）与 entropy（高熵）为独立合成负载；后两者支持 -entities（动态实体数，含玩家）、-state-bytes（状态字节数）和 -datagram-size（数据报上限）。-encoding（快照编码）使用 delta（差量）或 full（完整）；-seed（随机种子）固定各客户端代理的随机序列。完整与差量采用相同第 3 版协议、完整长度分组和每秒 30／15 次逻辑／快照频率。

当前两模式的服务器均使用相同 BBRv1（瓶颈带宽与往返传播时间第一版）标准控制器，客户端均使用传输库默认策略；对照不能只为差量模式更换控制器。固定种子使各代理的概率和随机序列可复现，但不同报文数量会推进随机数序列，不能宣称两模式每一包经历相同损伤。弱网配对成员使用独立服务器、负载进程与代理套接字，可并行运行但共享测试主机；十分钟资源测量单独运行。实际命令、二进制摘要和源码冻结清单保存在相应报告目录。

TotalApplicationBytes（总应用字节）为服务器累计可靠及数据报发送字节，加所有客户端累计上行发送字节。包含首次加入、续接、输入、操作和基线确认；不加客户端接收字节，避免重复计算同一消息。被替换客户端的最终字节和实体更新计数先归档。TrafficDurationSeconds（流量统计时长）覆盖首次连接前至最终计数采集，区别于资源测量窗口。原 PerClientPayloadBytesPerSecond（每客户端下行速率）继续保留原口径。

ExpectedEntityUpdates（计划实体更新）记录每帧各在线连接计划覆盖的记录量；SentEntityUpdates（已提交实体更新）记录成功交给传输库的记录量；AppliedEntityUpdates（实际应用更新）记录客户端真正接受的运动记录。发送成功不证明公网到达，计划编码字节也不等于发送字节。快照替换和实际提交量一同报告，不能以省略工作满足压缩率。

终点采集期间快照仍在发送、接收，各房间与客户端的累计计数来自不同读取时点。客户端应用量可能略高于此前取得的服务器提交量，不能以两者相减或相除计算严格的全局投递率；原始报告也不能重建共同截止时点的精确差分。总应用字节只累计两方向发送端计数，不把接收计数再加一次；各成员的实际流量窗口仍单独保留。

每个远端动态实体独立统计 EntityAges（显示年龄记录）。房间相对时间以 QPC（系统高精度计数器）或平台单调时钟计量，通过五次控制通信选择最短区间保守校准；误差写入 ClockCalibration（时钟校准记录）。显示年龄使用 SampleWithInfo（带来源信息采样）的实际 SourceTime（来源时间），不能用客户端收到包的时刻或其他实体的最新状态代替。预热五秒，十毫秒桶提供第 95 百分位上界；缺实体、保持末状态均记入。短于评估窗口时 DisplayAgeEvaluated（已评估年龄）为假。

标准负载在解除弱网的边界起算恢复时间，以仅返回小结果的操作冻结模拟；期间仍发送零输入。每二十毫秒检查三类状态逐字节一致，操作和观察耗时都计入一秒预算。客户端的完整状态和可靠变更计数不得增加；基线确认和操作结果本身可以通过可靠流。资源回收采样安排在恢复检查之后。

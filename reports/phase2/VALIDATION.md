**计时修正：** 审查发现旧计时会把 Windows（微软操作系统）上的部分短步骤记录为零。因此本阶段最终房间数据改用 QPC（系统高精度计数器），重新执行弱网与十分钟测试。时钟回归测得最小正间隔 100 纳秒，竞态检测下为 400 纳秒。实现依据 [微软高精度计数器说明](https://learn.microsoft.com/en-us/windows/win32/api/profileapi/nf-profileapi-queryperformancecounter)及[频率读取说明](https://learn.microsoft.com/en-us/windows/win32/api/profileapi/nf-profileapi-queryperformancefrequency)。首版原始报告保留，不用于精确比较亚毫秒性能。

原始结构化报告中的 StepP99（单步第 99 百分位）、StepMax（单步最大值）、RTT（往返延迟）等持续时间字段以纳秒保存。

单步统计包括房间推进、游戏回调、快照编码及入队，不包括后台网络写入。第 99 百分位采用 0.1 毫秒一格的直方图并报告所在格的上界。处理器、分配和内存均是整个测试进程的合计，包含服务器、全部客户端及启用的代理。长测启用处理器采样，前段与回归、短测重叠；这是开发机实测，不是独占硬件的极限吞吐结果。

## 功能与安全边界

| 验证项 | 结果与证据 |
|---|---|
| 首次连接、隔离房间、拾取唯一性、重复输入、乱序及迟到快照 | 原有回归通过 |
| 保留期间续接、过期拒绝、主动退出、容量占用释放、关闭续接 | 会话回归通过 |
| 错误凭证、跨房间凭证、服务器重启、关闭房间 | 明确拒绝续接，不创建新玩家 |
| 在线接管、并发续接、旧连接关闭与迟到输入 | 玩家、角色编号及代数保留；旧连接失去控制 |
| 操作取消、未入队取消不发送、结果丢失后跨连接重试 | 原编号与原负载返回缓存结果，不重复拾取 |
| 超时后更换同编号负载 | 客户端立即拒绝；服务器也校验原负载，避免误用迟到结果 |
| 延迟从 300 毫秒切换到正常网络后重新同步 | 响应后重新计冷却，暂时繁忙不误断连 |
| 整批非法变更、超大报文、初始化及更新异常 | 房间结束且可读取原因；不广播部分批次；其他房间继续推进 |
| 房间结束和退出清理 | 在线及保留会话只清理一次；某个清理回调异常仍继续清理其他会话 |
| 慢客户端 | 可靠积压触发剔除且凭证失效；正常客户端继续推进 |
| 快照队列 | 1000 次覆盖测试后仍只有最新一批，记录 999 次替换 |
| 证书校验、报文大小与输入窗口 | 原有边界回归通过 |

完整回归在竞态检测下通过，主测试包耗时 40.498 秒，合并语句覆盖率 64.5%。命令行程序的独立运行不计入该覆盖率。另对关闭清理、冲突重试及非法批次隔离连续执行十次带竞态检测的回归。

证据：[完整竞态测试](tests-race.txt)、[覆盖率](coverage.txt)、[重复边界回归](final-regression.txt)、[测试程序竞态短测](harness-race.txt)。测试程序竞态短测为 2 房间 × 4 人、5 秒负载加一秒恢复，验证了并发换连接路径；十分钟性能运行本身未开启竞态检测。

独立服务器和客户端的六秒演示完成拾取、临时断开与续接，玩家编号和拾取数量不变。见 [独立进程演示](cli-resume.txt)。

## 弱网与实际断网

每档 16 客户端、16 道具，20 秒负载加一秒恢复；每 3 秒轮换一人续接。全部叠加单向抖动 30 毫秒、5% 丢包、2% 重复和 2% 额外乱序。

| 往返延迟 | 单步第 99 百分位 | 单核口径处理器占用 | 每客户端下行字节/秒 | 续接和一秒内收敛 |
|---:|---:|---:|---:|---|
| 0 毫秒 | 0.3 毫秒 | 21.65% | 8961 | 通过，[原始数据](weak-0ms.json) |
| 150 毫秒 | 0.2 毫秒 | 21.57% | 8961 | 通过，[原始数据](weak-150ms.json) |
| 300 毫秒 | 0.2 毫秒 | 26.71% | 8961 | 通过，[原始数据](weak-300ms.json) |

每档均完成六次续接，网络恢复并停止移动一秒后，所有客户端权威状态和本地预测均与本房间服务器一致。零往返延迟这一档仍有抖动和丢包，不代表无损网络。

实际断网另通过将双向代理丢包率设为 100%，等待真实连接空闲超时后，从新路径续接；保留原角色。该场景、三档弱网续接及高延迟切低延迟重新同步均在 [完整竞态测试](tests-race.txt)中通过。没有通过修改本机网络配置来模拟断网。

短测不作为长期内存稳定性证据。带宽为服务器下行应用负载，不含传输头、加密、确认、重传和上行；不能据此推算公网账单。

## 8 房间 × 16 人十分钟结果

最终运行 601.013 秒（600 秒负载，加一秒恢复和采样）。128 个客户端保持在线，完成 157 次续接，八个房间均通过独立状态比对、资源和单步预算检查。

所有房间单步第 99 百分位均为 0.3 毫秒，低于 10 毫秒目标；其中一个房间出现 21.11 毫秒的最大值。因此这是百分位目标达标，不是每一步都有硬性十毫秒上限。

| 房间 | 在线/保留会话 | 成功续接次数 | 单步第 99 百分位（毫秒） | 单步最大值（毫秒） | 收敛 |
|---|---:|---:|---:|---:|---|
| bench-0（测试房间） | 16/0 | 19 | 0.3 | 3.30 | 通过 |
| bench-1（测试房间） | 16/0 | 19 | 0.3 | 4.09 | 通过 |
| bench-2（测试房间） | 16/0 | 19 | 0.3 | 1.88 | 通过 |
| bench-3（测试房间） | 16/0 | 20 | 0.3 | 2.10 | 通过 |
| bench-4（测试房间） | 16/0 | 20 | 0.3 | 2.92 | 通过 |
| bench-5（测试房间） | 16/0 | 20 | 0.3 | 6.84 | 通过 |
| bench-6（测试房间） | 16/0 | 20 | 0.3 | 21.11 | 通过 |
| bench-7（测试房间） | 16/0 | 20 | 0.3 | 1.45 | 通过 |

每个客户端只与自己的房间比较：逐实体校验编号、拥有者、生命周期代数和状态字节，并检查本地预测。原始数据：[十分钟逐房间报告](soak-8x16-10m.json)。

| 指标 | 实测 |
|---|---|
| 进程处理器占用（单核口径） | 54.82% |
| 进程处理器占用（32 逻辑处理器总量口径） | 1.71% |
| 第 60 秒堆 / 末次堆 | 55.14 / 53.99 MiB（兆二进制字节） |

| 第 60 秒协程数 / 末次协程数 | 1935 / 1935 |

| 合计下行运动数据报负载 | 1144295 字节/秒 |

| 最终累计输入队列丢弃 / 快照替换次数 | 0 / 0 |

每 30 秒主动垃圾回收后采样。内存验收以第 60 秒为基线，末次堆允许基线的 25% 加 4 MiB（兆二进制字节）余量，协程数允许增加 8 × 16。该阈值用于发现明显增长；十分钟通过不能证明任意运行时长都没有泄漏。

在线数及保留会话数逐房间记录。本轮采样时均为 128 个在线、0 个保留会话；周期续接间隔很短，采样未捕获临时保留窗口。 采样不是瞬时峰值；保留会话占位、到期释放另由会话回归验证。可靠队列每连接最多 64 条，快照最多一批，房间控制与输入队列分别最多 128 条和 256 批。

处理器分析见 [采样汇总](cpu-profile.txt)和[原始采样](soak-cpu.prof)。采样最集中于 runtime.cgocall（运行时调用桥，自身采样占比 29.45%）；Room.step（房间推进）累计占比 1.65%。采样只用于定位方向，完整进程处理器时间取自操作系统统计。

## 构建、模糊测试和编码基准

- 静态检查及 Windows（微软操作系统）构建通过；Linux（开源操作系统）amd64（64 位处理器架构）与 macOS（苹果桌面操作系统）arm64（64 位精简指令集架构）交叉编译通过，未在这两种系统原生运行。见 [构建记录](builds.txt)。
- 协议模糊测试运行 15 秒、两个工作进程，4224 次执行，无崩溃。第 2 版固定输入、加入封包和会话头偏移均有回归。见 [模糊测试](fuzz.txt)。
- 16 实体快照编码三次微基准中位数 561.2 纳秒/次，每次 1980 字节、12 次内存分配。只测编码，不代表网络吞吐或完整房间耗时。见 [编码基准](bench.txt)。

## 复验与交付

在项目根目录执行：

~~~powershell
go test './...' '-count=1'
go test '-race' './...' '-count=1'
go vet ./...
go test -run '^$' -fuzz '^FuzzDecode$' -fuzztime 15s -parallel 2
go run ./cmd/check -duration 10m -rooms 8 -clients 16 -resume-every 30s -report reports/phase2/soak-8x16-10m.json -cpuprofile reports/phase2/soak-cpu.prof
go run ./cmd/check -duration 20s -clients 16 -resume-every 3s -rtt 300ms -jitter 30ms -loss 0.05 -duplicate 0.02 -reorder 0.02 -report reports/phase2/weak-300ms.json
~~~

竞态检测需要配置兼容的 C（编程语言）编译器，详见[主接入文档](../../README.md)。接口及示例见[续接说明](../../RESUME.md)，字节样例见[第 2 版协议](../../PROTOCOL.md)。

仅提供进程内恢复。凭证不得记录日志；服务器重启后失效。游戏回调必须快速、不阻塞；隔离可恢复异常，不处理进程退出或无限阻塞。没有添加角色重生、持久化、账号认证、带宽压缩或引擎适配。

首版报告逐文件与首版压缩包核对摘要一致，见[历史保留核对](history-preserved.txt)。第二阶段源码、说明与报告单独打包为 statesync-v2.zip（项目压缩包），首版压缩包保持原样。

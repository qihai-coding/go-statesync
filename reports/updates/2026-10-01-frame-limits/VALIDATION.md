# 可靠报文接收边界维护报告

日期：2026 年 10 月 1 日。协议保持第 2 版，合法报文字节布局不变。

## 问题和修复

旧服务器接收客户端请求时，沿用完整世界状态的 262144 字节上限。实际合法客户端报文更小；只发送声明长度为 101 或 525 字节的长度头，服务器仍等待消息体。真实加密连接已复现两个场景，见[修复前记录](before.txt)。

共享读取函数现在接受方向与阶段对应的上限，读取四字节长度头后立即检查，超长时不分配或读取消息体：

| 接收方向与阶段 | 消息体上限 | 根据 |
|---|---:|---|
| 服务器接收加入／续接握手 | 100 字节 | 版本与类型 2、名称长度 2、名称 64、凭证 32 |
| 服务器接收加入后的可靠控制消息 | 524 字节 | 版本与类型 2、操作编号 8、负载长度 2、负载 512 |
| 客户端接收服务器可靠消息 | 262144 字节 | 保留完整状态和批量变更的容量 |

以上均不含四字节流长度前缀。共享函数同时保留全局上限，调用方传入更大限制也不能绕过。服务器使用协议违规关闭码 4 拒绝超长请求，已加入的违规会话不能续接。

修改：[协议读取](../../../protocol.go)、[服务器接收](../../../server.go)、[客户端接收](../../../client.go)。没有增加依赖或后台任务。

## 验证

| 检查 | 结果 |
|---|---|
| 只提供超长长度头 | 共享函数立即返回协议错误；真实连接在 500 毫秒检查窗口内收到关闭码 4 |
| 合法边界 | 三档上限均能完整读取；真实客户端使用 64 字节房间名成功加入 |
| 最大操作负载 | 512 字节负载到达游戏逻辑；示例游戏正常拒绝该业务内容，后续合法操作仍成功 |
| 隔离及凭证失效 | 超长控制请求的会话不能续接，同房间正常客户端继续确认移动输入 |
| 针对性回归 | 三项新增回归各连续十次通过，未启用竞态检测；见[记录](targeted.txt) |
| 全量竞态检测 | 通过，主测试包耗时 40.525 秒；见[记录](tests-race.txt) |
| 新增报文读取模糊测试 | 两个工作进程、15 秒预算，完成 224947 次输入检查，无失败；命令总耗时 16.042 秒，见[记录](fuzz-frames.txt) |
| 静态检查与当前平台构建 | 通过；Go（编程语言）1.26.5、Windows（微软操作系统）64 位，见[记录](builds.txt) |

全量回归包含往返延迟 0／150／300 毫秒的弱网和续接矩阵、实际断网、高低延迟切换、慢客户端、生命周期及房间异常隔离。新增检查位于[协议测试](../../../protocol_test.go)和[续接集成测试](../../../resume_test.go)。最终源码摘要见[校验值](SOURCE.sha256)。

本次未重新进行十分钟压力测试或跨平台构建。第二阶段及前两次维护的报告完整保留，历史性能数据不作为本次重新测量的结果。

## 边界

这次限制的是应用层单条可靠消息的缓冲区，不是整个加密连接的内存占用。未超长但未发完的消息仍遵循已有连接和读取期限；本次没有新增通用消息读取超时。数据报路径和状态同步算法不变。

## 复现命令

在项目根目录执行；竞态检测需按[运行说明](../../../README.md)配置本机编译器。

~~~powershell
go test -run 'TestFrameDirectionalLimits|TestServerRejectsOversizedRequestsFromPrefix|TestLargestLegalClientFrames' -count=10 .
go test -race -count=1 ./...
go test -run '^$' -fuzz '^FuzzReadFrame$' -fuzztime 15s -parallel 2 .
go vet ./...
go build ./...
~~~

交付 statesync-v2-frame-limits.zip（项目压缩包），包含第二阶段断线续接及此前两次维护。旧压缩包和历史报告保持原样。
